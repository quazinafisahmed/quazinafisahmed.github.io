01 —Overview

Built a controlled home cybersecurity lab using a Linux Mint laptop and a Mac Mini connected over a shared home Wi-Fi network to simulate and analyze network reconnaissance activity. Wireshark was used to capture and inspect traffic, identify abnormal ARP behavior, and analyze TCP/IP communication patterns generated by network scanning tools.

The capture file contains 20,561 packets collected over a 227-second window, with traffic spanning ARP host discovery, ICMP probing, TCP port scanning, and normal background internet activity.

04 —Step-by-Step Methodology
STEP 1 — Environment Preparation

Configured both machines on the shared home Wi-Fi subnet. The Mac Mini was set up as a target by enabling SSH and hosting a temporary HTTP server to generate realistic traffic.

# macOS target — start HTTP server
python3 -m http.server 8080

# Linux Mint — install tools
sudo apt update && sudo apt install wireshark nmap bettercap
STEP 2 — Verified Connectivity

Confirmed bidirectional communication between the two systems using ICMP and HTTP before beginning the capture.

ping 192.168.x.xxx
# Browser test: http://192.168.x.xxx:8080
STEP 3 — Captured Baseline & Reconnaissance Traffic

Started Wireshark and launched Bettercap for ARP-based host discovery across the full /24 subnet, while Nmap probed the target for open ports.

# Start Bettercap ARP host discovery
sudo bettercap -iface wlan0

# Port scan the target
nmap 192.168.x.xxx

# Key Wireshark filters used
arp
icmp
tcp.flags.syn == 1
ip.addr == 192.168.x.xxx

06 —Findings & Limitations
Confirmed
[+]
High-frequency ARP broadcast enumeration — 16,552 requests from a single host sweeping the full /24 subnet in under 4 minutes.
[+]
Sequential subnet probing — ARP targets progressed .0 → .253 in order, a clear signature of automated host discovery.
[+]
Open ports identified — TCP ports 80 and 443 returned SYN-ACK responses from 192.168.0.174.
[+]
External communications observed — 23 unique external IPs contacted, consistent with normal macOS background traffic.
Limitations
[-]
No ARP cache poisoning confirmed — duplicate IP-to-MAC mappings were not observed; sweep did not progress to full MITM interception.
[-]
Limited port scan data — only 12 SYN packets recorded, suggesting a narrow scan scope.
[-]
Single capture point — a router-level TAP or mirror port would provide a more complete view of all LAN traffic.

08 —Lessons Learned
  • ARP reconnaissance generates significant broadcast traffic even without successful MITM interception — volume alone is detectable.
  • Network scanning behavior is identifiable through traffic timing and sequencing, not just packet content.
  • Wireshark display filters are essential for isolating suspicious activity in high-volume mixed captures.
  • Modern home networks may reduce visibility of traditional ARP poisoning indicators due to AP client isolation.
  • Capturing from a single endpoint limits visibility — a router-level capture would provide a fuller picture.
